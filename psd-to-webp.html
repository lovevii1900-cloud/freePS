When WEBP is the wrong choice

WEBP is a delivery format, not an archive format. If you need to keep editing layers later, save the JSON project file as well — the WEBP export is flattened, so layers are baked into one image. And if you are handing artwork to a print shop or a client on old software, PNG is still the safer hand-off.

Privacy note

Because the PSD is parsed locally, an unreleased design, a client file, or anything under NDA never touches a server during this workflow. That is the same reason freePS suits client work in general — the privacy claim is about where parsing happens, not about the export format.

Photos vs graphics: does WEBP treat them the same?

WEBP handles both, but the win is biggest on photos and complex artwork, where it generally beats PNG on file size. For flat graphics with few colors — a logo, an icon — PNG is already small, so the saving is modest and PNG's universal compatibility may matter more. Either way, export both from the same PSD and compare: the editor lets you switch formats without re-opening the file.

Does my PSD get uploaded?

No. Every PSD is parsed locally in your browser memory, so the file never leaves your device.

Does the WEBP keep my layers?

No — WEBP is a flat image export. If you need layers later, also save the JSON project file, which freePS can re-open with layers intact.

Is WEBP better than PNG or JPG?

For the web, usually yes: WEBP generally gives smaller files than PNG for the same image and supports transparency, unlike JPG. For print hand-offs or very old software, PNG is still the safer choice.

Can I export PNG or JPG instead?

Yes. The same editor exports PNG (with transparency), JPG, WEBP, or a JSON project file.
